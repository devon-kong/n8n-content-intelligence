## Reproduce offline

After the [Python setup](../python/README.md), run from the repository root:

```bash
python3 scripts/check_public.py
python3 -m unittest discover -s checks -p 'test_*.py'
node --test checks/*.test.mjs
(cd python && python -m pytest -q)
python scripts/compare_demos.py
```

Node 22.16+ is required for the SQLite test adapter and optional n8n demo. These
checks use synthetic input, temporary databases and mocked HTTP. They do not
contact production services. Package installation is a separate network step.

To regenerate the existing Catch fixture and offline evidence:

```bash
node scripts/demo_n8n.mjs > assets/evidence/n8n-fixture-run.json
python scripts/demo_python.py > assets/evidence/python-fixture-run.json
python scripts/record_validation.py
```

The engine demo is opt-in and documented separately. Its runner validates the
actual execution state, expected endpoint, write/call counts, structured output
and controlled failure causes before publishing a bounded JSON report.

## Reliability changes verified in this update

- All three Entry workflows reject a response containing multiple matching rows
  or `has_more=true`. The query requests two rows to detect duplicates.
- Expired processing locks become uncertain; subsequent attempts remain blocked.
- Both n8n and Python block persisted uncertain calls across later attempts;
  Python tests also reopen the database to model process restart.
- Explicit retry authorization updates exactly the selected uncertain row and
  writes an audit entry atomically. Active/already-reviewed rows and incomplete
  CLI confirmations are rejected. [Recovery procedure](paid-call-recovery.md).

These mechanisms retain their existing task-key scope and are not an exactly-once,
no-double-charge or tenant-isolation guarantee.

## Pending gates before live use

1. **Original connector execution:** install and record compatible community-node
   versions; bind actual credentials/child versions and validate runner packaging
   in a dedicated environment. Import-only acceptance is insufficient.
2. **Live integration and model quality:** dedicated tables and service accounts;
   inspect actual feed authentication, write serialization, summaries, structured
   fields, metrics and reruns. Evaluate generated facts against their sources.
3. **Coverage:** the engine fixture covers one Benchmark path with Metrics disabled.
   Accept the other entries, News Summary and Metrics separately before claiming
   the entire set is delivery-ready.
4. **Concurrency/recovery:** test simultaneous Entries, persistence and uncertain
   remote requests in the real topology. Local lock tests do not prove that topology.
5. **Python benchmark parity:** structured benchmark fields are not implemented.
6. **Live visual evidence:** current n8n captures belong to the isolated mock-boundary
   demo. Actual Feishu screenshots and a live-service recording remain outstanding.

A green offline badge does not close these gates.
